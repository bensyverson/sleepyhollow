# Spike: how `sleepy ax` reads the accessibility tree

*2026-08-20 · spike-ax (leaf r3uhE) · status: concluded — recommendation at the end*

**Question.** The vision doc leaves one mechanism question open for `sleepy ax`:
does the verb read the macOS AX/NSAccessibility tree of the headless WKWebView,
compute roles/names/states itself with injected JavaScript, or both? The verb's
contract (indented outline by default — `button "Publish" (disabled)` — and
`--format json` for the full tree) is fixed either way.

**Answer.** JavaScript computation, injected in an isolated world. The native
path is empirically dead for a windowless, non-app CLI process on public API;
the JS path produced a faithful, agent-ready outline of both a nontrivial
fixture and a real page, and the algorithm we must own is bounded and testable.

## Method

All evidence comes from a throwaway prototype (a small SwiftPM executable,
`axspike`, in the session scratchpad — deliberately not in this repo). It hosts
a headless `WKWebView` (explicit frame, `WKWebsiteDataStore.nonPersistent()`,
main-thread run-loop pump, no `NSApplication` unless noted) and has four modes.
Every figure below names the invocation that reproduces it; because the
scratchpad is ephemeral, the appendix carries the decisive native-probe code
so the negative result stays reproducible (the JS prototype needs no such
preservation — its logic is described in full below and becomes product code).
Environment: macOS 26.5.2, Swift 6.3.3, 2026-08-20. The package targets macOS
12 — availability of every API used is addressed under *macOS 12 floor* below.

The fixture (`fixture.html`) is a publish-an-article form: labelled inputs
(`<label for>`, `aria-label`, `aria-labelledby` + `aria-describedby`), a native
checked checkbox, an ARIA checkbox with `aria-checked="mixed"`, a radio
fieldset, a select, **a disabled named button** (`<button disabled>Publish`),
an `aria-disabled` link-button, `aria-expanded`/`aria-pressed` buttons, a
`role=presentation` table, a `title`-named icon button, landmarks, headings, a
visually-hidden-but-accessible note, `display:none` content, `aria-hidden`
decorative noise, and a `progressbar` with `aria-valuenow`.

## Candidate 1: macOS AX / NSAccessibility — dead on public API

**Bare walk** (`swift run axspike native fixture.html`): the in-process
NSAccessibility walk from the web view reports

```
class=WKWebView role=AXGroup enabled=true legacyRole=AXGroup
  (no AX children)
```

No tree at all. This is WebKit's documented-in-behaviour gating: the WebContent
process builds its AX tree only when an assistive client is active.

**Forced walk** (`swift run axspike nativeforce fixture.html`): initializing
`NSApplication` (activation policy `.prohibited`) and setting the
`AXEnhancedUserInterface` attribute on the app — the flag VoiceOver sets, via
the *deprecated* legacy `accessibilitySetValue:forAttribute:` — makes exactly
one child appear after a settle:

```
class=WKWebView role=AXGroup enabled=true legacyRole=AXGroup
  class=NSAccessibilityRemoteUIElement
    (no AX children)
```

That child is the crux. In WebKit's two-process architecture the page's AX tree
lives in the WebContent process; the UI process holds only this remote proxy.
`NSAccessibilityRemoteUIElement` is AppKit SPI (no public header), and it
resolves only through the HIServices assistive-client machinery — which
requires the caller to hold the TCC Accessibility grant and a window-server
registration. The same run confirms `AXIsProcessTrusted: false`, and
`AXUIElementCreateApplication(getpid())` yields an element whose every
attribute copy fails. So the native path requires, cumulatively: a deprecated
legacy API to force AX on, SPI or the AX client API to cross the process
boundary, and a per-binary accessibility permission a CLI cannot self-grant
(and which would be a bizarre install step for an agent tool). Each alone is
disqualifying for the product; noted here because the *tree does exist* — this
is a gate, not an absence — and a future macOS could open it.

## Candidate 3: anything built in — nothing exposed

`swift run axspike probe fixture.html` evaluates a feature probe in the page:

```json
{"computedRole":"undefined","computedLabel":"undefined",
 "getComputedAccessibleNode":"undefined","internals":"undefined",
 "accessibilityController":"undefined",
 "elementRoleReflection":"checkbox","ariaMixinChecked":"mixed"}
```

WebKit's page JS has no computed-role/computed-name API (the AOM proposals
never shipped; `computedRole`/`computedLabel` exist only behind WebDriver, i.e.
safaridriver, which is not our stack). What *does* exist is ARIA attribute
reflection (`el.role`, `el.ariaChecked`) — attribute echoes, not computed
values, but handy primitives for candidate 2. `WKWebView` itself exposes no
accessibility-snapshot API of any kind.

## Candidate 2: injected JS computation — works, and the gap is ownable

The prototype (`axquery.js`, ~280 lines) implements a subset of the ARIA role
mapping, AccName 1.2, and state extraction: computed-style visibility pruning,
`aria-hidden` subtrees, explicit-role validation, HTML implicit roles,
presentation-role stripping with required-owned-element inheritance, the
AccName precedence chain (`aria-labelledby` → `aria-label` → host-language
labels via `el.labels`/`alt`/`legend`/`caption` → name-from-content →
`title` → `placeholder`), and states (disabled incl. `fieldset:disabled` and
`aria-disabled`, checked incl. `mixed` and `indeterminate`, expanded, pressed,
selected, current, required, readonly, heading level, values). It runs through
`callAsyncJavaScript` in `WKContentWorld.defaultClient` — exactly the seam the
product will use — and renders both the outline and the JSON tree.

**Fixture** (`swift run axspike js fixture.html axquery.js`), excerpt:

```
form
  textbox "Article title" (value="Sleepy Hollow ships")
  searchbox "Search tags"
  textbox "Summary"
  checkbox "Notify subscribers" (checked)
  checkbox "Sync some platforms" (checked="mixed")
  group "Visibility"
    radio "Public" (checked)
    radio "Private" (not checked)
  button "Publish" (disabled)
  button "Save draft"
  button "Schedule" (disabled)
button "Advanced options" (not expanded)
```

The flagship query — *is there a button named Publish, and is it disabled?* —
is answered by a single grep-able line. Hidden and decorative content is
correctly absent (0 hits for the `display:none` and `aria-hidden` markers);
the visually-hidden screen-reader note is correctly present.

**Real page** (`swift run axspike js https://www.wikipedia.org axquery.js`):
124 outline lines, all sensible — `heading "Wikipedia The Free Encyclopedia"
(level=1)`, a `navigation "Top languages"` of named links, `search` containing
`searchbox "Search Wikipedia"` and a `combobox` with the selected option,
`button "Read Wikipedia in your language" (not expanded)`, `contentinfo`
landmarks. No garbage nodes, no missed interactive elements on inspection.

**Fidelity, honestly.** AccName is fiddly, and the spike met the fiddliness
directly: the first prototype run had three real spec bugs — `role=presentation`
on a table did not strip its `tbody/tr/td` (presentational inheritance through
required owned elements), and `listitem` and `paragraph` wrongly received
name-from-content (ARIA excludes both; `paragraph` prohibits naming). All
three were found *by reading the outline against the fixture* and fixed in
minutes. That is the shape of this approach: a stream of small, individually
fixable spec deviations, caught by fixtures. Known remaining gaps, none
structural: no text leaves yet (a bare `paragraph` line loses its text — the
product should emit static-text children); no `::before`/`::after` content in
names (readable via `getComputedStyle(el, "::before")`, so implementable); no
shadow-DOM descent (open roots reachable, closed roots invisible to everyone);
cross-origin iframes need per-frame injection (a document-start user script in
all frames can post each frame's `WKFrameInfo` back, then the computation runs
per frame — public API, not prototyped); `aria-owns` reparenting unhandled.
The product's honest framing: `sleepy ax` emits *the page's computed semantics
per WAI-ARIA and AccName*, not a byte-identical copy of WebKit's internal
AX tree — the same posture Testing Library takes, and the right one, since the
spec is the contract pages are written against.

**How much algorithm we own.** The full production surface is roughly the
prototype's ~280 lines grown to 600–1,000 lines of dependency-free JS. The
ceiling is well charted: the W3C publishes conformance fixtures
(web-platform-tests `accname/` and `wai-aria/role/`), so the algorithm can be
regression-tested against the spec's own cases in our fixture-server harness.
Per the dependency rule, we implement rather than vendor `dom-accessibility-api`
(the Testing Library implementation): it is TypeScript, Node-shaped, and
tangled with jsdom concerns; our injected script must be a single plain-JS
file anyway, and the subset an agent needs is smaller than its surface.

## macOS 12 floor

Everything the JS path needs is public API well inside the floor:
`callAsyncJavaScript` and `WKContentWorld` (macOS 11+), `WKUserScript`
per-world injection (11+), `getComputedStyle`, `Element.labels`, `:scope`, and
ARIA attribute reflection (Safari 12–15 era). The spike machine runs macOS
26.5.2, so the native-path *negative* result technically speaks for modern
macOS only — but every gate it hit (AX client trust, remote-element SPI,
deprecated forcing attribute) is old architecture, present since WebKit2;
macOS 12 has no additional public door.

## Recommendation

**Implement `sleepy ax` as injected JS computation in the isolated world; do
not pursue the macOS AX API.** Ship the algorithm as a single bundled JS
resource owned by the library, sized 600–1,000 lines; grow it against WPT
accname/role fixtures served by the test fixture server; add static-text
leaves and pseudo-element name support before 1.0; document shadow-DOM and
cross-origin-iframe limits in the verb's `--help`. Revisit the native path
only if Apple ships a public headless AX snapshot API. "Both" is not worth it:
the native path's cost is an installation-time permission wall, which
contradicts the tool's zero-ceremony philosophy even where it works.

## Appendix: the native probe, preserved

The scratchpad prototype will evaporate; this is the code behind the
candidate-1 figures, verbatim enough to re-run in any headless-WKWebView
harness (load the fixture, pump the main run loop until `didFinish`, settle,
then call `axDescribe(webView, depth: 0, maxDepth: 12)`):

```swift
import ApplicationServices  // AXIsProcessTrusted, AXUIElement*
import WebKit

func axDescribe(_ node: Any, depth: Int, maxDepth: Int) {
    let indent = String(repeating: "  ", count: depth)
    guard let obj = node as? NSObject else { return }
    var bits = ["class=\(type(of: node))"]
    if let ax = node as? NSAccessibilityProtocol {
        if let role = ax.accessibilityRole() { bits.append("role=\(role.rawValue)") }
        bits.append("enabled=\(ax.isAccessibilityEnabled())")
    }
    if let legacy = obj.perform(NSSelectorFromString("accessibilityAttributeValue:"),
                                with: "AXRole" as NSString)?.takeUnretainedValue() {
        bits.append("legacyRole=\(legacy)")
    }
    print("\(indent)\(bits.joined(separator: " "))")
    guard depth < maxDepth else { return }
    var children = (node as? NSAccessibilityProtocol)?.accessibilityChildren() ?? []
    if children.isEmpty,
       let legacyKids = obj.perform(NSSelectorFromString("accessibilityAttributeValue:"),
                                    with: "AXChildren" as NSString)?
           .takeUnretainedValue() as? [Any] {
        children = legacyKids
    }
    if children.isEmpty { print("\(indent)  (no AX children)") }
    for child in children { axDescribe(child, depth: depth + 1, maxDepth: maxDepth) }
}

// The "nativeforce" variant additionally runs, before creating the web view:
let app = NSApplication.shared
app.setActivationPolicy(.prohibited)
app.perform(NSSelectorFromString("accessibilitySetValue:forAttribute:"),
            with: kCFBooleanTrue, with: "AXEnhancedUserInterface" as NSString)
print("AXIsProcessTrusted: \(AXIsProcessTrusted())")  // → false
// …and afterwards inspects AXUIElementCreateApplication(getpid()), whose
// every AXUIElementCopyAttributeValue call returns a non-.success error.
```
